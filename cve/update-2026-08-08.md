## Méthode retenue

1. Repérer le noyau réellement actif vs noyau installé (`uname -r` vs `/var/run/reboot-required.pkgs`).
2. Récupérer le changelog Debian officiel de la version cible (paquet source `linux`, pas `linux-image-*`/`linux-signed-*`) — voir [debsecan.md](debsecan.md).
3. Extraire les CVE du changelog, interroger l'API officielle CVE (MITRE) pour description + CVSS/sévérité — script [analyse-cve-update.py](../scripts-externes/vulnx/analyse-cve-update.py).
4. Pour les CVE critiques, vérifier sur le serveur si le sous-système concerné est réellement chargé/exposé avant de conclure au risque.
